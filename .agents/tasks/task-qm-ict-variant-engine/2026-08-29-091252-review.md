# QM/ICT XAUUSD detection + variant engine, blocks 2-7 (v1)

Blocks 2-7 assemble a causal QM/ICT detection stack (NY session tagging, ERL/IDM/POI/SMT detectors, a full state machine, and a variant-grid runner) on top of the pre-existing `v1_lab` validation infra. The governing constraint — every unconfirmed rule must be a tunable parameter or explicit variant switch, all code deterministic and causal, and the OOS outcome reported honestly without manufacturing a winner — is honored well. Every open rule surfaces as a `VariantConfig` field or CLI flag with a non-pre-optimized default; the locked items (MSS body-close + displacement, H4→H1→M15→M5 backbone, DST math, both NY legs neutral) are implemented exactly and cross-checked. The variant runner uses a pre-declared IS/OOS split, reuses `pipeline.py` unmodified, and reports 0 eligible / 0 PASS / all-INSUFFICIENT honestly rather than crowning a variant.

Watch for: one documented variant switch (`reentry`) is wired into `VariantConfig` and the docstring but never read by the engine and never swept by the grid — an inert degree of freedom (confirmed). The `qm_ob` POI variant is effectively a no-op on real data because an order block is almost always found, so it produces byte-identical results to baseline (confirmed). Both are honesty/coverage gaps, not causality violations.

**Verdict**: APPROVED

## High-level view

Causality holds throughout. Each detector derives structure only from swings confirmed by the decision bar (`index + pivot <= t`), the ERL cross-TF path restamps resampled bars at their bucket *close* so a higher-TF level is only visible after it has closed, and the M5 simulation is strictly forward with same-bar SL/TP resolved conservatively as SL-first. The self-checks include explicit truncation tests (append future bars, assert the decision is unchanged), which is the right way to prove no-lookahead in this codebase.

The parameterization discipline is genuine. Nothing subjective is hard-coded to a pre-selected value: SMT pair, POI type, SL/TP mode, buffers, RR gates, IDM-clear requirement and precision, pivot, displacement, ERL lookback and source TF, session scope, and risk caps are all `VariantConfig` fields, and the self-checks demonstrate that toggling a switch flips the outcome on the same data. The one exception is `reentry`, which is declared but never consulted.

The variant runner's split is pre-declared as a fixed calendar constant (`2026-02-01`), documented as the a-priori chronological midpoint, and the report carries the multiple-testing disclosure and the IS-is-exploration-only caveat. It imports `pipeline.py` and `metrics.py` verbatim and does not alter any threshold; `MIN_OOS_TRADES=200` and `M1_MIN_PF=1.20` are confirmed intact. The INSUFFICIENT outcome (21 variants, 0 eligible) is the intended result of a selective engine on ~12 months of data.

The main gaps are coverage-honesty rather than correctness: an inert `reentry` switch and a `qm_ob` variant that cannot discriminate because its confluence is near-universally present.

### Causality across resampling and higher-TF level mapping

The cross-timeframe path is where a lookahead bug would most plausibly hide. `resample_causal` restamps each resampled bar at `bucket_start + span` (the close instant), and `_map_higher_tf_levels` assigns to each M15 bar the ERL levels from the most recent HTF bar whose close time `<= ` the M15 bar's timestamp. A still-forming HTF bucket has a close time in the future relative to the current M15 bar, so it is never consulted — the higher-TF level a bar sees is always one that has already closed, and the ERL raid test compares the M15 bar's own high/low against that already-closed level. HTF swing confirmation adds further lag (a level activates several HTF bars after its extreme prints), which is conservative, not leaky.

### Parameterization vs hard-coding — where it holds and where it slips

Everything unconfirmed is a switch, and the self-checks prove each switch is a real gate (toggle one parameter, assert the outcome flips on identical data). The state machine's B/C pair (IDM never cleared ⇒ no trade with `idm_clear_required=True`, trade reappears with `False`) shows the mandatory-vs-optional rule is not baked in.

The slip is `reentry`. It is listed in the docstring's variant table with a default of `False` and is a `VariantConfig` field, but `grep` finds no read of it anywhere in `qm_state_machine.py` — the re-entry-after-stop-out behavior it names does not exist (only `max_trades_per_day` is enforced). It is also absent from the grid and from the runner's switch-coverage assertion, so it is a silent, inert degree of freedom that contradicts the "every unconfirmed rule is a tunable switch that is actually exercised" claim. Implement and sweep it, or remove it.

### POI confluence variants and the qm_ob degeneracy

`detect_poi` builds the left-shoulder QM zone causally (structure break = first body close beyond the neckline after head confirmation), and `qm_fvg` is a genuine discriminator — the D2 self-check constructs a QM with an OB but no FVG and shows `qm_fvg` suppresses it. `qm_ob` is effectively inert: `find_order_block` scans backward all the way to bar 0 for the last opposing candle, which in real data almost always exists, so the OB requirement rarely removes anything. The results confirm it — `poi_qm_ob` is byte-identical to `baseline` (155 trades, same PF/exp/DD). It is enumerated and honestly reported but cannot inform an A/B decision because it never binds. Constraining the OB to the immediate displacement leg (a bounded lookback rather than scan-to-zero) would make the requirement selective.

Related reporting artifact: `tp_partial` (`partial_be_trail`) is modeled as the `fixed_rr` target level, so `tp_partial` and `tp_fixed_rr` are identical result rows. The docstring is honest that this is a proxy, but the per-variant table and the trial count present them as two independent trials.

### SMT data dependency and the correlation guard

With no partner series in the repo, `smt_pair='off'` yields zero signals; `xag`/`dxy` without `--pair-csv` report the dependency and disable SMT rather than fabricating a partner, and the `_resolve_smt` note is surfaced verbatim into the report's data-dependency section. The rolling Pearson guard is causal (window ends at the swing bar) and the DXY expected-sign inversion (`-1`) is a documented parameter. The `smt_xag`/`smt_dxy` rows are therefore identical to baseline here and flagged as unresolved data dependencies rather than results.

### Trade simulation and cost/risk handling

`simulate_trade` resolves a bar that touches both SL and TP as SL-first, which never flatters the strategy. Costs (spread + commission) and `risk_per_trade` are pre-declared parameters, not invented per trade. Defaults set spread/commission to 0.0, so the real run is gross-of-cost — a pre-declared parameter the user is expected to set, with M4 cost-stress remaining a PENDING pipeline stage. Disclosed rather than hidden, but worth noting the headline OOS figures carry no transaction cost.

### Variant runner: pre-declared split, unmodified pipeline, honest verdict

The IS/OOS boundary is a fixed constant (`SPLIT_BOUNDARY = 2026-02-01`) documented as chosen a priori at the dataset midpoint, with unparseable timestamps conservatively assigned to IS so they never count as unseen OOS evidence. `pipeline_verdict` imports `pipeline.py`'s own threshold constants and stage functions without redefinition; the thresholds (`MIN_OOS_TRADES=200`, `M1_MIN_PF=1.20`, K2/K3 ratios, M6/M8) are confirmed unchanged by the block 2-7 commits. The ranking key is documented as a reading aid, not a selection, and the verdict column is the only judgement. With 21 variants and none clearing the 200-OOS-trade bar, the report states INSUFFICIENT / no robust edge and declares no winner; the 200-trade bar is not worked around.

The runner self-check covers CSV format, deterministic byte-identical report, and switch-is-wired-through — but its switch-coverage `must` list omits `reentry` and `erl_lookback`, so its "every open switch exercised" print overstates coverage.

### Reuse of pre-existing infra

`qm_detect` (load_ohlc, atr_wilder, detect_swings, detect_mss), `metrics.py`, and `pipeline.py` are imported and reused, not reimplemented; ERL/IDM/POI/SMT all import the shared parser and swing rule, and the runner imports the engine, metrics, and pipeline verbatim. No reimplementation of the locked detectors or the verdict engine was found.
