### `reentry` is wired into the cap, causal, and swept without being tuned

The cap check is now `used >= max_trades_per_day + reentry_slots`, where `reentry_slots` is the count of same-day SL exits when `cfg.reentry` is True and zero otherwise, so the default path is byte-identical to the old `used >= max_trades_per_day`. The slot counter (`stops_per_day`) is incremented only when a completed trade's M5 simulation resolved to `exit_kind == "sl"`, and setups are processed in `mss_events` (chronological index) order. Selfcheck case F builds a two-setup day where the first short stops out on a sharp rally, sets `max_trades_per_day=1`, and asserts exactly one entry with `reentry=False` versus two with `reentry=True`, both on the same calendar date and the second at a strictly later index — a real discriminator, not an inert field. That the swept `reentry_on` variant comes out *worse* than baseline (PF 0.80 vs 1.11, net negative) is evidence the rule was exercised honestly rather than pre-optimized.

The honesty caveat is that the slot is granted at trade-append time based on the first trade's *resolved* exit, and a stop can resolve later in wall-clock time than a subsequent setup's M5 entry. So the gating decision "this later setup is allowed because an earlier one stopped out" can, in a live-causal sense, lean on an exit that hasn't happened yet at the later entry. This is a cap-relaxation look-ahead, not a price look-ahead — every trade's entry/SL/TP is still fixed from bars at or before its own entry, and each simulation is strictly forward. Practical effect on the reported numbers is nil (`reentry` defaults False; the `reentry_on` variant is INSUFFICIENT at 91 OOS trades). A stricter formulation would count only stop-outs whose exit timestamp precedes the candidate entry bar.

### Bounded `ob_lookback` keeps `qm_ob` causal and makes it (and its bound) discriminate

`find_order_block` now computes `lo_bound = max(0, break_index - lookback)` and scans `[lo_bound .. break_index-1]`, so the OB must sit on the immediate displacement leg rather than anywhere back to bar 0. All scanned indices are strictly `< break_index`, preserving causality. `lookback <= 0` restores the unbounded scan, and the default (5) is documented as an open parameter, not a winner. Selfcheck case C2 constructs a series whose only opposing candle sits far back at index 1 with a clean down-displacement leg, then asserts `lookback=3` returns None while `lookback=0` finds index 1 — proving the bound binds. On real data the fix resolves the v1 degeneracy: `poi_qm_ob` is now 157 trades / 74 OOS versus baseline's 155 / 72 (no longer byte-identical), and the separate `ob_lb_3` row (75 OOS, PF 1.24) differs from `poi_qm_ob` (74 OOS, PF 1.15), so both the confluence requirement and its lookback bound are genuine A/B switches.

### `tp_partial` equivalence is disclosed structurally and the trial count is honest

`_equivalent_variants` indexes every `fixed_rr` variant by its rounded `fixed_rr` value and maps any `partial_be_trail` variant sharing that value to its `fixed_rr` sibling — a config-level (not results-level) detection, so the annotation stays honest even if the data changes. The equivalence surfaces in three places: the report's multiple-testing note ("Effective (distinct) trials: 24" with the explicit `` `tp_partial` == `tp_fixed_rr` `` pair), the ranked table (`tp_partial (== tp_fixed_rr)`) and per-variant section, and a new `equivalent_to` column in `variant_results.csv`. The CSV confirms `tp_partial` and `tp_fixed_rr` carry identical metrics (170 total / 77 OOS, PF 1.3262), and `equivalent_to=tp_fixed_rr` is populated only on the proxy row. Selfcheck case A2 asserts the detector flags `tp_partial → tp_fixed_rr` and leaves genuinely distinct variants (`baseline`, `tp_fixed_rr`) unflagged. The row is retained for traceability rather than dropped, keeping the enumeration complete while refusing to count it as independent evidence.

### Coverage assertion now matches what is swept

The runner selfcheck computes the set of `VariantConfig` fields the grid actually varies and asserts every open switch appears in it. The `must` list gained `ob_lookback`, `erl_lookback`, and `reentry`, and the grid gained rows that vary each: `ob_lb_3` (via `qm_ob` + `ob_lookback=3`, correctly paired with `qm_ob` so the bound isn't a no-op under plain `qm`), `erl_lb_3`/`erl_lb_8`, and `reentry_on`. `EXPECTED_N` moved 21→25. The `erl_lb_3` (69 OOS) vs `erl_lb_8` (73 OOS) divergence confirms `erl_lookback` is a live parameter, not just `erl_tf`.

`pipeline.py` is unchanged by the fix commit and remains an imported-verbatim module; `MIN_OOS_TRADES=200` and `M1_MIN_PF=1.20` are intact, and the runner still calls the pipeline's own stage functions without redefining thresholds.
